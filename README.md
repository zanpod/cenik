# EPO.SI — Digital Menu & Table Ordering

Multi-tenant digital menu and ordering system for bars, restaurants, and
cafes. The guest scans a QR code at the table, browses the menu, and places
an order; staff see incoming orders in real time on the admin dashboard,
organized by table.

- **Frontend:** plain HTML/CSS/JS (no framework, no build step) → Netlify
- **Backend:** Supabase (PostgreSQL, Auth, Realtime, Storage)
- **Look:** dark theme, glassmorphism, blue-purple gradients, mobile-first
- **Multi-tenant:** one codebase + one database serves every venue, data
  isolation enforced with Row Level Security (RLS)

## Structure

```
/
├── index.html              -- Landing page
├── menu/index.html         -- Guest menu + ordering
├── admin/                  -- Admin panel (login, dashboard, menu, tables, history, settings)
├── css/                    -- common.css, menu.css, admin.css
├── js/                     -- supabase-config.js + per-page logic
├── assets/                 -- notification.wav, logo.svg
├── supabase/schema.sql     -- Tables, RLS, storage, realtime
├── supabase/seed.sql       -- Sample data (demo venue "Bar Lipa")
├── netlify.toml / _redirects
```

## Setup

### 1. Supabase

1. Create a new Supabase project.
2. In the **SQL Editor**, run `supabase/schema.sql` (creates the tables, RLS
   policies, the `menu-images` storage bucket, and enables Realtime on
   `orders` + `order_items`).
3. (Optional) Run `supabase/seed.sql` for the demo venue **Bar Lipa**.
4. Under **Authentication → Providers**, enable **Email** (password).
5. Create an admin user (Authentication → Users → Add user) and link them to
   a venue — uncomment the `profiles` INSERT at the bottom of `seed.sql` and
   fill in the user's `id` from `auth.users`.

### 2. Configure keys

Edit `js/supabase-config.js` and fill in your **Project URL** and **anon
public key** (Project Settings → API). The anon key is public by design —
it's protected by RLS policies. Also set `APP_DOMAIN` to your Netlify domain
(used when generating QR codes).

Alternatively, inject the values via `window.EPO_SUPABASE_URL`,
`window.EPO_SUPABASE_ANON_KEY`, and `window.EPO_APP_DOMAIN` (e.g. a Netlify
snippet injection), without editing the file.

### 3. Netlify

1. Connect the repository or drag-and-drop the folder onto Netlify.
2. No build step needed (`publish = "."`). `netlify.toml` / `_redirects`
   handle redirecting `/menu/*` to the single menu page.
3. **Domain:** this system is a **separate Netlify site** from the agency
   site `Epo.si` (agencijaepo.si) — they're two different
   repositories/deploys. For the links generated by `agencijaepo.si/demo` to
   actually work, add the custom domain **`demo.agencijaepo.si`** to this
   Netlify site:
   - Netlify Dashboard → this site → **Domain settings → Add a domain** →
     enter `demo.agencijaepo.si`.
   - Netlify shows the exact CNAME record (usually pointing to
     `<your-site>.netlify.app`) — add it with your `agencijaepo.si` DNS
     provider.
   - Once DNS propagates (a few minutes to a few hours) and Netlify issues an
     SSL certificate, `demo.agencijaepo.si/menu/...` and
     `demo.agencijaepo.si/admin` will work.
   - `APP_DOMAIN` in `js/supabase-config.js` adapts automatically (it reads
     `location.origin`), so no further code changes are needed after this
     step.

## Usage

- **Guest:** `https://<domain>/menu/<venue-slug>?table=<qr_code_token>`
  (generate QR codes in the admin panel → Tables).
- **Staff:** `https://<domain>/admin` → log in → real-time order dashboard
  (sound + system notification on new orders).

## Demo for prospective customers

**agencijaepo.si/demo** (repository `Epo.si`) is a **public** page — no login
required. Anyone can create a new demo: fill in a name, colors, menu, and
**their own email address**, and the system automatically emails them access
(the guest link + admin login). A logged-in admin (on the same page) also
sees delete/reset-password buttons and gets the password shown on screen, not
just by email.

Every demo gets its own **admin (owner) user account**
(`<slug>@demo.agencijaepo.si` + password) when it's created, so a prospect
can explore the FULL app themselves — not just the guest menu, but the admin
panel too (tables/QR codes, live orders, menu editing, settings). Through RLS
(`current_tenant_id()`), that account can only see and edit its own demo
venue — the same mechanism that already separates real customers from each
other, so granting full access is safe.

The backend is four Supabase Edge Functions:
- **`provision-demo`** — creates/updates a demo + admin account. Works both
  publicly (email required, password sent ONLY by email, rate-limited — see
  migration `011_demo_signup_log.sql`) AND as an admin call (logged-in
  caller, no rate limit, password also returned on screen).
- **`delete-demo`**, **`reset-demo-password`**, **`convert-demo`** — admin
  only (require a valid EPO.SI login). `convert-demo` sets
  `tenants.is_demo = false` (optionally also replaces the admin account's
  placeholder email with the customer's real address) — this makes the venue
  stop being a "demo": it disappears from the `/demo` list and
  `cleanup_demo_orders()` no longer cleans it up.

Install all four once via the Supabase Dashboard (see the comment at the top
of each file). For `provision-demo` to send email, also set two secrets
(Edge Functions → Secrets):
- `RESEND_API_KEY` — API key from [resend.com](https://resend.com) (can be
  the same one `Epo.si` already uses for `send-contact-email`, or a new one).
- `FROM_EMAIL` — sender address, verified on Resend (e.g.
  `demo@agencijaepo.si`).

Demo orders older than 24 hours are cleaned up **automatically every hour**
via `pg_cron` (migration `013_schedule_demo_cleanup.sql`) — no manual run
needed. For those who prefer a command line, there's also an equivalent Node
tool in `scripts/demo/` (no public self-service part, no email, no
conversion to a real customer) — see
[`scripts/demo/README.md`](scripts/demo/README.md).

## Guest order security

All public (anonymous) orders go through `submit_guest_order()` — a SQL
function (migration `012_secure_guest_orders.sql`) that reads the real
price/name/stock from `menu_items` itself (the client-side price/name in
`js/menu.js` is display only, not the source of truth) and validates the
venue + table + stock before creating the `orders`/`order_items` rows.
Direct anonymous `INSERT` on those two tables is blocked — this prevents a
guest from submitting an order with a forged (e.g. €0.01) price, or
injecting line items into another table's or venue's order.

## Real time

The dashboard subscribes to Supabase Realtime for `orders` (INSERT/UPDATE)
and `order_items` (INSERT), filtered by `tenant_id`. New orders appear
instantly, a chime plays (`assets/notification.wav`, with a synthesized Web
Audio fallback), and a system notification is shown (if permitted).

## Notes

- Order line-item prices are **denormalized** (`item_name`, `item_price` are
  stored at order time), so later menu changes don't affect order history.
- Timestamps are stored in UTC and displayed in `Europe/Ljubljana`.
- Orders older than 24 hours drop off the live dashboard (still visible in
  History).
- All end-user-facing text is in Slovenian (the target market).

## Security (RLS)

Every table has RLS enabled:
- Anonymous guests can **read** active venues/categories/items/tables and
  **insert** orders — they cannot read or modify orders.
- Logged-in staff can access **only** their own venue's data (via
  `profiles.tenant_id`), which prevents cross-tenant access.
